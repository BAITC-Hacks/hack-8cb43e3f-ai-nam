# Выбор и подключение ИИ-модели

Система работает с **любым OpenAI-совместимым сервером** (`/v1/chat/completions`, опционально `/v1/embeddings`).
Без модели все функции доступны: включается детерминированный режим (правила, текстовое сходство, шаблоны).

## Рекомендуемые модели (русский и казахский)

| Железо | Текстовая модель (Ollama) | Эмбеддинги | Vision (схемы) |
|---|---|---|---|
| CPU / 8–16 ГБ ОЗУ | `qwen2.5:3b-instruct` или `gemma3:4b` | `bge-m3` | — (OpenCV + Tesseract) |
| GPU 8 ГБ | `qwen2.5:7b-instruct` (по умолчанию) | `bge-m3` | `qwen2.5vl:3b` |
| GPU 12–16 ГБ | `qwen2.5:14b-instruct` или `gemma3:12b` | `bge-m3` | `qwen2.5vl:7b` / `gemma3:12b` |
| GPU 24 ГБ+ | `qwen2.5:32b-instruct` | `bge-m3` | `qwen2.5vl:32b` |
| Облако | `gpt-4o-mini`, `claude-*`, `qwen-*` через OpenRouter и т.п. | `text-embedding-3-small` | та же модель, если мультимодальная |

Для казахского языка можно использовать специализированные модели (например, KazLLM или Sherkala на базе Llama 3.1)
через vLLM или llama.cpp. Имя модели указывается в админ-панели.

Модель используется в «узких» задачах с коротким контекстом (вердикт по паре формулировок, резюме по списку выводов),
поэтому даже 3–7B-модели дают полезный результат.

## Подключение

### Ollama на своём компьютере
```bash
ollama pull qwen2.5:7b-instruct && ollama pull bge-m3
```
Панель администратора → **ИИ-модель** → пресет «Ollama (локально)» → **Проверить подключение** → **Сохранить**.
Если приложение запущено в Docker, укажите `http://host.docker.internal:11434/v1`.

### Ollama внутри docker compose
```bash
# .env
LLM_PROVIDER=openai
LLM_BASE_URL=http://ollama:11434/v1
LLM_MODEL=qwen2.5:7b-instruct
LLM_EMBED_MODEL=bge-m3
```
```bash
docker compose --profile ollama up -d --build
docker compose logs -f ollama-pull     # дождитесь «models ready»
```
Для GPU раскомментируйте блок `deploy` у сервиса `ollama` в `docker-compose.yml` (нужен NVIDIA Container Toolkit).

### LM Studio / vLLM / llama.cpp
| Сервер | Запуск | base_url |
|---|---|---|
| LM Studio | вкладка Developer → Start Server | `http://localhost:1234/v1` |
| vLLM | `vllm serve Qwen/Qwen2.5-7B-Instruct --port 8001` | `http://localhost:8001/v1` |
| llama.cpp | `llama-server -m model.gguf --port 8080` | `http://localhost:8080/v1` |

### Облачные API
Укажите URL провайдера и ключ (`LLM_API_KEY` или поле в админ-панели). В ответах API ключ маскируется.
Учтите, что фрагменты документов будут переданы внешнему сервису.

## Что именно отправляется модели

| Задача | Содержимое запроса |
|---|---|
| Проверка сопоставления | две формулировки функций с названиями подразделений и номерами пунктов |
| Проверка дублирования / конфликта | 2–5 формулировок из вывода |
| Резюме заключения | сводка и список выводов (id, тип, значимость, заголовок, подразделения) |
| Вопросы агенту | до 14 найденных фрагментов документов и выводов |
| Распознавание схемы | изображение схемы |
| Перевод (пакет документов KZ) | формулировки функций |

## Проверка без модели

`make mock-llm` запускает мок-сервер (`scripts/mock_llm_server.py`), который отвечает в тех же форматах.
Так можно увидеть работу ИИ-шагов (проверка выводов, резюме, чат) на любом компьютере без GPU.
